# 선택 품질 검토 동의 배포 점검

2026-10-19. API 계약은 [API.md](API.md#선택-품질-검토-동의-2026-10-19)를 따른다.

## 적용 범위

- 기본 설치 인증을 유지하면서 품질 검토 개인정보 이용과 원고 이용 허락을 별도 저장한다.
- 기존 설치/Job은 자동 동의로 간주하지 않는다. 마이그레이션 기본값은 false/null이고
  과거 품질 전용 이벤트·피드백·평가 필드는 정리한다. 기본 결과·확정 선택은 유지한다.
- 품질 검토 SQL은 현재 설치 동의와 업로드 당시 동의 ID가 일치하는 행만 읽는다.
  담당자 목록·활동·갤러리·제품/품질 지표·공백 관측과 직접 파일 접근에 모두 적용한다.
  `/ops`의 서비스 가동 상태·요청 수 같은 기본 운영 집계는 계속 제공한다.
- 원본/파생 파일은 90일, 연결 평가정보는 365일 이내다. 품질 철회 시 권한과 품질 전용
  데이터를 제거하고 90일이 지난 작업도 삭제한다. 그보다 최근의 공유 원본·결과는 기본
  목적의 남은 기간만 유지한다. 사용자 개별/전체 삭제 요청이 우선한다.
- 동의 증빙은 별도 테이블에서 종료 후 1년까지 보관한다. 관리자 검토 API로 노출하지 않는다.

## 배포 순서

1. DB 백업 및 기존 S3 `inputs/`, 파생 산출물 prefix의 90일 lifecycle을 확인한다.
2. 이전 BFF API와 워커를 모두 교체한다. 마이그레이션은 현재 시작 과정에서 실행되므로
   구 버전의 품질 수집/관리자 경로가 함께 남아 있는 상태로 앱을 배포하지 않는다.
   적용 뒤 기존 Job이 `quality_review_jobs`에 없는지 확인한다.
3. 기존 관리자 페이지를 새로고침한다. 구 버전에서 발급한 단기 S3 URL은 만료 전까지
   남을 수 있다. 새 버전은 관리자 인증 프록시만 발급한다. 이미 내려받은 검토 복사본·공백
   관측 export는 이 API 변경으로 원격 삭제되지 않으므로 기존 운영 절차에 따라 정리한다.
4. 새 앱을 배포한다. 기존 자격증명으로 분석/내보내기 가능, 선택 동의 기본 미체크,
   두 허용 모두 선택한 뒤 업로드한 작업만 검토 가능한지 확인한다.
5. 한 허용을 해제하고 저장한 뒤 관리자 목록·상세·원본/BVH/썸네일/FBX가 차단되는지,
   다시 동의해도 이전 작업이 돌아오지 않는지 확인한다. 기존 설치 인증은 유지되어야 한다.

이 변경은 운영 DB/S3에 직접 실행하거나 운영 서비스에 배포하지 않았다. DB 정리 코드가
포함되므로 배포 전 백업과 전체 인스턴스 교체 순서를 확인한다. 정책 본문의 기본 동의 버전
변경이나 모든 사용자에 대한 약관 재동의는 이 선택 동의 API와 별도의 배포 결정이다.

## 검증

- PGlite의 실제 PostgreSQL 엔진으로 전체 스키마/반복 마이그레이션과 Hono 라우트,
  저장소 함수를 실행한다. 기존 설치 기본값, 부분 허용, 이후 Job만 허용, 이벤트/피드백의
  동의 ID 검증, 관리자 SQL, 철회/재동의, 기본 결과 유지, 90일 만료를 확인한다.
- Hono 미들웨어 테스트에서 변환 중 철회가 발생한 응답도 파일 대신 404로 대체되는지 확인한다.
- PGlite는 단일 연결 테스트다. 다중 PostgreSQL 연결의 실제 경합, AWS 객체 삭제,
  실추론·Converter 및 네이티브 앱 전체 흐름은 배포 환경 통합 점검이 필요하다.
- 전체 테스트에서 Windows 임시 경로가 POSIX 절대 경로 검사를 통과하지 못하는 기존 실패
  4건(`body-selection/neutral.test.ts` 1건, `shapeRuntime.test.ts` 3건)을 확인했다.
  동일한 기준 `origin/develop` 소스를 별도 빌드해 같은 4건이 실패함을 재현했다.
