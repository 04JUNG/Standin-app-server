# 광고 링크와 신규 설치 연결

웹 UTM → standin://campaign?source=instagram&campaign=open-beta&creative=meta-poster-a (또는 meta-hook-a) → 앱의 별도 선택 동의 → 설치 인증을 사용한 서버 연결.

기존 웹 측정·품질 검토 동의와 별개이며 Google/Meta로 앱 이용 이벤트를 보내지 않는다. IP, 클립보드, 지문으로 기기를 추정하지 않는다. 링크는 공유·수정 가능하므로 광고 조회의 증명이 아니라 사용자가 확인한 캠페인 링크 연결이다.

## API

설치 헤더 인증이 필요한 `/v1/installations/current/acquisition`:
- POST `{creative:"meta-poster-a"|"meta-hook-a",consent:true,version:"2026-10-29"}` → `{creative}`.
- 최초 서버 등록 후 24시간 이내, 아직 연결한 적 없는 설치만 원자적 UPDATE. 동일 광고 재시도는 성공, 다른 광고 덮어쓰기·철회 후 재연결·오래된 설치는 409.
- GET → `{creative:string|null}`. DELETE → 연결값 삭제. 동의 시각은 재귀속 방지를 위해 유지하며 설치 전체 삭제 때 삭제.
- 잘못된 동의/소재 400, 설치 인증 없음 401. 측정 실패는 앱 이용을 차단하지 않는다.

`GET /v1/admin/product?days=7`의 acquisition 배열과 기존 운영 대시보드에서 소재별 신규 설치 코호트를 확인한다. analyzed/selected/exported는 각각 중복 제거 설치 수이며 연결 동의 이후 작업만 센다. active는 최근 24시간 서버 인증 접속이다. unknown은 설치 수만 표시하고 이용은 광고 집계에 사용하지 않는다. 기존 quality_review_* 기반 제품 지표와 대상이 다르다. 별도 광고 연결 동의만을 근거로 원본 jobs에서 성공 여부를 합산하며 원고/후보 상세/개별 기록을 응답에 넣지 않는다.

보관: 광고 구분·버전은 90일 정기 유지보수 때 제거, 철회 즉시 제거, 전체 데이터 삭제 시 설치 행과 함께 삭제. 알 수 없는 소재는 저장하지 않는다. 과거 설치·과거 분석은 소급 귀속하지 않는다. 재설치/여러 기기는 여러 설치로 셀 수 있고 개발·테스트 트래픽 자동 제외는 없다.

## 배포

서버 additive migration → 클라이언트 0.2.4 이상 Windows/macOS 검증·서명 배포 → 랜딩 버튼 활성 순서. 랜딩은 GitHub의 최신 정식 릴리스가 0.2.4 이상임을 확인했을 때만 버튼을 보인다. 구버전에서는 새 링크가 동작하지 않는다. 수동 테스트: 두 소재를 각각 새 설치로 연결, 분석·저장, 관리자 집계에서 중복 없이 증가 확인. 거절/철회/24시간 경과/일반 아이콘 실행도 확인. 운영 테스트 설치는 보고서에서 구분해 해석한다.
