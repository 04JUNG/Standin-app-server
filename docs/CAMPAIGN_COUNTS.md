# 소재별 건수 집계

기존 설치별 광고 연결은 선택 동의를 유지한다. 이 경로는 설치/작업 테이블을 조회·조인하지 않고 공통 소재별 건수만 합산한다. 모든 통계가 법적으로 익명이라는 선언이 아니며 식별자 해시·IP 매칭·거절 우회를 허용하지 않는다.

## 계약

POST /v1/metrics/campaign-counts: JSON {v:1, creative:meta-poster-a|meta-hook-a, event:first_run|first_analysis_success}. 최대 160바이트, 다른 키 거절. 인증·쿠키·설치 헤더·쿼리 불허. 본문 없는 204, 입력 오류 400/413/415, 출처 403, 메서드 405, 속도 제한 429, 비활성/저장 실패 503. CORS는 설정 출처만, credentials 불허.

요청 ID/로그/인증/IP 미들웨어 전에 종료한다. 오류·하위 경로도 부모 로거로 넘기지 않는다. 기본 서비스 보안 로그는 유지한다. IP는 네트워크에서 수신될 수 있지만 이 경로에서 저장·해싱·개별 이용 재연결하지 않는다. 원시 이벤트 로그·추적 SDK를 추가하지 않는다.

테이블은 campaign_daily_counts(day, creative, event, count)만. 서버 수신 한국 날짜, 셀별 하루 10000건, 프로세스 전체 분당 60 요청 상한. 공유 라벨을 아는 외부인이 위조할 수 있으므로 인증된 전환이 아니다. 유지관리에서 90일 이전 셀 삭제. 개인별 행이 없어 합산 수를 개별 삭제하지 않는다.

## 관리자

기존 인증된 GET /v1/admin/marketing?days=N에 campaignCounts: {enabled,since,until,minimumCell:5,rows:[{creative,first_run,first_analysis_success}]} 추가. 전날까지 N개 한국 날짜, 5 이상 정수 또는 null. 0과 1–4 모두 null. 총합/성공률/당일 실시간/설치 필터/개별 행 없음. 범위 간 차분이 가능한 단순 소수 셀 숨김이지 수학적 익명성 보장은 아니다.

이벤트별 수신 날짜라 실행과 성공은 같은 코호트가 아니다. 성공률·고유 사람 수·광고 단계별 승자를 계산하지 않는다. 개발자 제외 설정 미적용. 기존 Meta·운영·선택 연결 표와 합산하지 않는다.

## 앱과 배포

v0.2.8부터 공통 소재가 포함된 서명된 전용 설치 파일은 앱 열기 링크 없이 새 등록 시 소재를 전달한다. 기존 설치에는 적용하지 않는다. 서버 요청·테이블·억제 기준은 동일하다. 일반 파일은 기존 24시간 앱 열기 링크를 유지한다. 설치 파일 공유는 광고 조회의 증명이 아니므로 사람 수/광고 조회로 해석하지 않는다.

v0.2.7 새 등록 및 첫 화면 고지 이후에만 상태 생성. 기존 설치 업그레이드 제외. 등록 24시간 내 첫 지원 링크, 최대 7일 내 신규 이미지 분석의 첫 정상 결과 표시를 보고한다. 작업 ID는 앱 메모리에서 시작/성공 매칭에만 사용하고 전송하지 않는다. 문장 검색/기록/실패/중단/저장 제외. 7일 만료 후 다음 실행 시 상태 삭제, 소재는 성공 보고 시 삭제. 전송 전 플래그 저장, 실패 재시도 없음. 통신 실패/종료는 누락, 재설치/여러 창/변조는 중복 가능.

공개 고지 → 서버(기본 CAMPAIGN_COUNTS_ENABLED=false) → 로그 검증 후 beta 변수 true 재배포 → 승인된 v0.2.7 서명 빌드·딥링크·거절·신규 분석 검증 순서. 운영에 합성 이벤트를 보내지 않는다.

2026-10-31 읽기 전용 확인: api 도메인 ALB 직접 연결, 해당 ALB S3 access/connection 로그 false, WAF WebACL 연결 응답 없음. RDS default.postgres16, CloudWatch 로그 export 없음. 파라미터 null은 실제 런타임 부재를 입증하지 않는다. RDS 원격 주소는 BFF이며 이용자 IP를 SQL에 넣지 않는다. 활성화 직전 및 인프라 변경 시 ALB/WAF/APM/프록시 로그 재확인. 다른 경로 보안 로깅을 끄지 않는다.
